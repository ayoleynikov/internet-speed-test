# Замер скорости загрузки по URL

Небольшая CLI на **чистом Python** (стандартная библиотека): принимает URL, выполняет **10 последовательных** HTTP(S)-запросов, дожидается **полного** ответа, считает среднее время запроса, объём данных и скорость.

## Требования

- Python **3.10+** (проверено на 3.12)
- macOS / Linux
- Доступ в интернет — только когда вы сами гоняете скрипт на внешнем URL; тесты работают без сети

## Запуск

Из корня репозитория:

```bash
python3 -m measure "https://example.com/some-large-file.jpg"
```

Опции:

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `url` | — | Целевой `http://` или `https://` URL |
| `-n`, `--count` | `10` | Число **последовательных** запросов |
| `--timeout` | `60` | Таймаут **одного** запроса (секунды, конечное положительное число) |

Пример с меньшим числом запросов (для отладки):

```bash
python3 -m measure "https://example.com/file.bin" -n 3 --timeout 30
```

## Тесты

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Тесты поднимают локальный HTTP-сервер на `127.0.0.1` и **не** ходят в публичный интернет.

## Метрики и формулы

Для каждого запроса \(i\):

- \(t_i\) — время от начала запроса до полного чтения тела (`time.perf_counter()`), включая установку соединения, заголовки и потоковое чтение тела
- \(b_i\) — число **фактически прочитанных** байт (чанками по 64 KiB), без опоры только на `Content-Length`

Агрегаты по \(N\) запросам:

- **Скачано всего:** \(B = \sum_i b_i\)
- **Суммарное время:** \(T = \sum_i t_i\)
- **Среднее время запроса:** \(T / N\)
- **Скорость загрузки (основная):** \(B / T\)

### Единицы в выводе

| Обозначение | Определение |
|-------------|-------------|
| **MiB/s** | мебибайт в секунду: \(B / T / 2^{20}\) (1 MiB = 1024² байт) |
| **Mbit/s** | мегабит в секунду: \((B \times 8) / T / 10^{6}\) (1 Mbit = 10⁶ бит, как у провайдеров) |
| **KiB / MiB** в объёме | двоичные префиксы (1024) |

### Почему не «среднее арифметическое скоростей запросов»

Скорость печатается как **\( \sum b_i / \sum t_i \)**, а не как среднее \( (b_i/t_i) \). Так корректно складываются объём и время одного непрерывного сеанса: быстрый короткий и медленный длинный запросы вкладываются в общую скорость с весом по времени. Среднее арифметическое \(b_i/t_i\) завышает или занижает результат, если длительности запросов различаются.

## Политика ошибок

- Неверный URL (не `http`/`https`, пустой, без хоста) → код выхода **2**, сообщение в stderr
- Ошибка сети, таймаут, HTTP 4xx/5xx, оборванное тело (меньше заявленного `Content-Length`) → **1**, итог **не** печатается
- При сбое на \(k\)-м запросе предыдущие успешные запросы в сводку **не** попадают (нет ложного «успеха»)
- TLS: проверка сертификатов **включена** (`ssl.create_default_context()`)
- Нулевой объём или нулевое суммарное время → скорость **0**, без деления на ноль

## Ограничения

Это **не** полноценный тест скорости «как у ISP»: результат зависит от сервера, маршрута, HTTP-версии, сжатия, кэша CDN, лимитов и размера файла. Повторные запросы к одному URL часто попадают в кэш. Скрипт измеряет скорость загрузки **конкретного ресурса**, а не канала целиком.

## Выборы, не заданные в ТЗ

| Тема | Решение |
|------|---------|
| Таймаут по умолчанию | 60 с на запрос |
| HTTP-ошибки | 4xx/5xx считаются ошибкой (тело не идёт в метрики) |
| Редиректы | Следует стандартному поведению `urllib` |
| User-Agent | Фиксированный `measure-speed-cli/1.0` |

## Пример вывода (иллюстративный, не замер)

```
URL: https://example.com/image.jpg
Запросов: 10 (последовательно)
Скачано всего: 4.88 MiB (5117056 байт)
Суммарное время запросов: 12.340 с
Среднее время одного запроса: 1.234 с
Скорость загрузки: 0.396 MiB/s (3.318 Mbit/s)
```

## Что улучшить при большем времени

- Параллельные запросы и отдельный режим «как в ТЗ» (последовательный)
- Опциональный JSON-вывод, warmup-запрос вне статистики
- Явная проверка `Content-Length` vs факт для chunked без заголовка
- Настраиваемый User-Agent, вывод перцентилей по \(t_i\)
